# Edge CRM phone app

Android app for sales executives, built around their day: follow-ups, new leads and one-tap contact. It's Expo (React Native)
plus one Kotlin module, `modules/call-tracker`, for the optional call tracking, which reads the call log and uploads it without
JS so it works with the app closed. It talks directly to `api.edgeacademy.ae` with a per-device token. See
[docs/CRM.md](../../docs/CRM.md) for how calls are matched to leads.

It ships as an APK, not through Google Play.

## Run and build

```bash
pnpm --filter @edge/mobile typecheck
pnpm --filter @edge/mobile lint
pnpm --filter @edge/mobile apk      # signed release APK in apps/mobile/dist
```

Needs JDK 17 and the Android SDK (`ANDROID_HOME`). `android/` is generated by `expo prebuild` and isn't committed; native
code we own lives in `modules/` and `plugins/`.

`pnpm dev` and `turbo run build` skip this app on purpose (it has no `dev` or `build` script), and `deploy/deploy.sh`
leaves it out of the server's install.

### Which API it talks to

There's no env file: these are read when the APK is built, and a plain build uses production. Don't add `apps/mobile/.env`, because
Expo would use it for staff builds too.

| Setting                  | What it sets                                   | Default                                          |
| ------------------------ | ---------------------------------------------- | ------------------------------------------------ |
| `EXPO_PUBLIC_API_URL`    | The API                                        | `https://api.edgeacademy.ae`                     |
| `EXPO_PUBLIC_CRM_URL`    | The web CRM, for Forgot password and 2FA setup | `https://crm.edgeacademy.ae`                     |
| `EXPO_PUBLIC_UPDATE_URL` | Where it checks for updates                    | `https://crm.edgeacademy.ae/android/latest.json` |
| `EDGE_ALLOW_HTTP=1`      | Allows plain HTTP. Local test builds only      | Off                                              |

### Run on an emulator

```bash
pnpm --filter @edge/e2e stack    # API on :4100, web CRM on crm.localhost:3102, throwaway in-memory database
cd apps/mobile
EXPO_PUBLIC_API_URL=http://10.0.2.2:4100 npm run android
```

Use the stack, not `pnpm dev`: the root `.env` may point at a live database. The stack has only the demo accounts, such as
`sales@edgeacademy.local` and the super admin `admin@edgeacademy.local`, both with the password `ChangeMe!2026`. Your real
accounts don't exist there.

Debug and release builds are signed with different keys, so uninstall one before installing the other, or the install fails with
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`:

```bash
$ANDROID_HOME/platform-tools/adb uninstall ae.edgeacademy.crm
```

The emulator can't make real outgoing calls. Seed calls with `adb emu gsm call +971501234567`, then `adb emu gsm accept
+971501234567` and `adb emu gsm cancel +971501234567`.

### Test build against a local API

A release build, so it's how staff will experience the app:

```bash
EDGE_ALLOW_HTTP=1 EXPO_PUBLIC_API_URL=http://10.0.2.2:4100 pnpm --filter @edge/mobile apk
```

That produces `dist/edge-crm-<version>-test.apk`, which allows plain HTTP. Never give a `-test` APK to staff.

Test sideloading through the browser or Files app, not `adb install`: Android treats adb installs as trusted, so an adb
test proves nothing about what staff will get. `adb shell dumpsys package ae.edgeacademy.crm | grep packageSource` should
show `3` or `4`.

## Look and feel

Colours, fonts and the dark Ink surface are in `src/lib/theme.tsx`, and every shared component is in `src/components/ui.tsx`. Use
those rather than styling a screen by hand. Manrope is built into the APK by the `expo-font` plugin, so use `Text` and its variants;
`fontWeight` doesn't work with it on Android. Edge Green is only for text on dark surfaces: use `tone="accent"`, which turns to Deep
Emerald in light mode. Forms go inside `Sheet`, which keeps Save above the keyboard.

Call tracking is a quiet extra, so keep it out of Today and first impressions.

## Signing key

`pnpm apk` reads `~/.edge-crm/keystore.properties`, which points at `~/.edge-crm/edge-crm-release.keystore`. Neither is in
git.

**Back up both files somewhere other than this computer.** Android only installs an update signed with the same key. If
the key is lost, every phone has to uninstall the app and install it again.

## Permissions

| Permission                             | Why                                                                                                      |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `POST_NOTIFICATIONS`                   | Alerts and the prompt to add a call's outcome. Asked at first sign-in                                    |
| `CALL_PHONE`                           | One-tap dialling. Asked on the first Call. Without it the app opens the dialer with the number filled in |
| `READ_CALL_LOG`                        | Number, time, direction and length of calls. Only asked if call tracking is on                           |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Asks to run in the background. Only asked if call tracking is on                                         |

Don't add overlay, accessibility, usage stats, SMS or default-dialer access. Android restricts all of those for apps
installed outside a store, and Play Protect blocks some outright.

## What Android does to the tracker

Tested on Android 16 with a real sideload (`packageSource=3`):

| Situation                        | Result                                                                                    |
| -------------------------------- | ----------------------------------------------------------------------------------------- |
| Call ends, app in the background | Uploaded within about 5 seconds                                                           |
| App process killed               | Android restarts it. The first call afterwards can wait for the next run; nothing is lost |
| Phone restarted, app not opened  | Keeps working                                                                             |
| Battery saver and Doze           | Picked up as soon as the phone wakes                                                      |
| Force-stopped in Settings        | Stops until the app is next opened, which then catches up                                 |

The call log is the queue: each run re-reads from the last accepted upload minus 6 hours, and the server ignores repeats.
A late run costs nothing but time.

Other brands add their own battery rules, so check each model. Use the per-brand list in [docs/CRM-APP.md](../../docs/CRM-APP.md).

## Releasing an update

1. Bump `version` in `package.json` and `app.config.ts`, and `versionCode` in `app.config.ts`. Android refuses an update whose
   `versionCode` isn't higher than the installed one.
2. `pnpm --filter @edge/mobile apk`, and try it on a phone.
3. `EDGE_DEPLOY_HOST=user@server pnpm --filter @edge/mobile publish-apk`.

Phones check `https://crm.edgeacademy.ae/android/latest.json` when the app opens and offer the update. The app verifies the
download's SHA-256 before handing it to Android, and Android refuses anything not signed with our key.

Set `EDGE_MIN_VERSION_CODE` when publishing if the API changed in a way older apps can't handle: phones below it can't skip
the update.

## Push alerts

Alerts need a Firebase project, and everything else works without one:

1. Create a free project at the Firebase console and add an Android app with package `ae.edgeacademy.crm`.
2. Save its `google-services.json` as `apps/mobile/google-services.json`, then rebuild the APK.
3. On the server set `PUSH_MODE=live` and `FCM_SERVICE_ACCOUNT_JSON` (a Firebase service account key, as one line of JSON).

Until then `PUSH_MODE=mock` writes alerts to the worker log.
